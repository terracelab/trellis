# 문구 규격 (Content)

화면·사이트·문서에 들어가는 말의 규칙이다. 토큰이 색을 고정하듯 이 문서는 어휘와 문장 형태를 고정한다. 제품 UI 문구, 문서 사이트, 동봉 문서(`dist/docs`), 테라스원 소개 페이지가 모두 따른다. 소비 앱용 요약은 `docs/guides/content.md`(사이트 "문구")에 있다.

## 0. 기준으로 삼은 것

2026-11-07에 직접 확인한 디자인 시스템 첫 화면의 문장이다(JS로만 그려지는 Material 3 · Lightning · Fiori · TDS는 읽지 못했다).

| 시스템 | 첫 제목 | 바로 아래 문장 | 주요 버튼 |
|---|---|---|---|
| Primer(GitHub) | Primer | The design system for GitHub | Get started with Product UI |
| Carbon(IBM) | Let's make together | Carbon is IBM's enterprise-ready, open-source design system, shaped by the IBM Design Language. | Start designing · Start developing |
| Spectrum(Adobe) | Start with Spectrum | Spectrum is the system behind Adobe experiences, a shared language for turning ideas into products. | First stop, foundations · See all components |
| Atlassian | Better teamwork by design. | (없음. 바로 소식 목록) | Get started · See what's new |
| SEED(당근) | 당근의 디자인 시스템 SEED | SEED는 당근의 뿌리가 되는 디자인 시스템이에요. 컴포넌트, 인터랙션, 스타일을 하나의 기준으로 정의해 더 빠르고 일관된 사용자 경험을 만들 수 있게 해요. | (없음) |

공통점이 규칙이 된다.

1. **첫 문장은 "X는 Y의 디자인 시스템이다"** 다. 은유도, 약속도 아니다.
2. **둘째 문장은 들어 있는 것**(토큰 · 컴포넌트 · 패턴 · 지침)을 명사로 센다.
3. 멋을 낸 제목은 있어도 **한 줄**이고, 다음 문장이 곧바로 사실을 말한다(Carbon · Atlassian).
4. 버튼은 **시작하기 · 컴포넌트 보기 · 새 소식**처럼 다음 행동 그대로다.
5. 사이트 구조는 **Foundations · Components · Patterns · Content(문구) · Accessibility · Data visualization · Updates**로 거의 같다. Carbon · Atlassian · SEED는 2026년 현재 AI/에이전트 절을 따로 둔다.

문구 지침 자체는 Atlassian(Content), Carbon(Content), Polaris(Voice and tone · Grammar and mechanics)에 있다. 셋 다 "짧게 · 능동태 · 사용자 쪽 말로 · 사과하지 않기 · 결과를 말하는 버튼"을 공유한다. 이 문서는 그 틀에 한국 업무 관습과 테라스랩 제품 어휘를 얹은 것이다.

## 1. 목소리

Trellis의 말은 **업무 담당자 옆자리 선배**의 말이다. 정확하고, 짧고, 현장 용어를 그대로 쓴다.

| 성격 | 뜻 | 예 |
|---|---|---|
| 정확하다 | 현장에서 쓰는 이름을 바꿔 부르지 않는다. 숫자는 실제 값 | "11월 부가세 예정신고 마감 11월 25일" (O) · "세금 관련 일정이 다가옵니다" (X) |
| 짧다 | 한 문장에 한 가지. 제목은 20자 안쪽 | "결재 대기 12건" (O) · "현재 처리를 기다리고 있는 결재 문서는 총 12건입니다" (X) |
| 평서문이다 | 설명하지 설득하지 않는다. 느낌표 · 수식어 · 은유 없음 | "표로 볼 수 있습니다" (O) · "손쉽게 표로 전환하세요!" (X) |

### 문체는 자리마다 하나

| 자리 | 문체 | 예 |
|---|---|---|
| 제품 UI 본문 · 안내 · 메시지 | 합니다체, 짧게 | "저장했습니다", "거래처를 먼저 고르세요" |
| 버튼 · 메뉴 · 탭 · 라벨 | 명사 또는 동사 어간. 조사 · 마침표 없음 | 저장 · 결재 요청 · 거래처 · 전표 입력 |
| 문서 사이트 · 동봉 문서 · 테라스원 소개 | 합니다체 | "토큰은 색 · 간격 · 글자 값을 이름으로 고정합니다" |
| 레포 내부 규격 · 플랜 · 결정 | 한다체 | "값은 토큰에서 온다" |
| 코드 주석 | 한다체, 이유 중심 | `// 폰트는 패키지 안의 woff2. 설치형은 오프라인이다` |

해요체는 쓰지 않는다. 소비자 서비스의 말투이고 업무 도구의 말투가 아니다.

## 2. 문장 규칙

1. 한 문장에 생각 하나. 쉼표로 두 문장을 잇지 않는다.
2. 제목은 **명사구**거나 **짧은 평서문** 하나. 제목에 쉼표 · 콜론 · 줄표를 넣지 않는다.
3. 줄표(—)로 끼워 넣는 설명, 콜론 뒤에 답을 숨기는 구조, 괄호 안 보충은 쓰지 않는다. 문장을 둘로 나눈다.
4. 나열은 가운뎃점(` · `)으로 쓰고, 문장 안에서는 셋 이하다. 넷 이상이면 표나 목록으로 뺀다.
5. 수식어를 쓰지 않는다. 금지어: 손쉽게 · 간편하게 · 강력한 · 완벽한 · 혁신 · 매끄러운 · 직관적 · 스마트한 · 최적화된 · 놀라운 · 최고의 · 다양한(수를 적을 수 있을 때) · 수많은.
6. 능동 평서로 쓴다. "~할 수 있습니다"는 실제로 선택지일 때만, "~을 위한"은 한 문장에 한 번만.
7. 느낌표 · 이모지 · 인사말 제목("안녕하세요, 김과장님")을 쓰지 않는다. 홈 제목은 날짜나 맥락이다(D-35).
8. 영어는 고유명사와 코드 식별자에만 쓰고 코드 서체로 적는다. 멋으로 섞지 않는다(Seamless · Smart).
9. 숫자가 있으면 숫자를 쓴다. "다양한 차트"가 아니라 "차트 14종".
10. 금액 · 날짜 · 단위 표기는 §4를 따른다.

## 3. AI가 쓴 것처럼 읽히는 신호와 고치기

이 목록은 2026-11-07 Trellis 사이트 초안에서 실제로 걷어 낸 것이다. 새 문구를 쓰면 이 표로 한 번 거른다.

| 신호 | 왜 걸리나 | 초안 | 고친 것 |
|---|---|---|---|
| 은유 제목 | 제품 사실 대신 그림을 말한다 | 다섯 제품이 하나의 격자 위에서 같은 화면을 그린다 | 테라스랩의 디자인 시스템 Trellis |
| 세 토막 병렬 | 리듬만 남고 정보가 없다 | 토큰 한 벌에서 두 테마, 두 밀도 | 색 · 글자 · 간격은 토큰으로만 씁니다 |
| 대구 반복 | 한 번은 원칙, 두 번부터 말장난 | 이름과 props는 같고, 구현만 다르다 | 웹 · 네이티브 · Django가 같은 이름을 씁니다 |
| 의인화 | 주어가 사실을 가린다 | 에이전트도 같은 문서를 읽는다 | 문서는 패키지 안에 들어 있습니다 |
| 조건 제목 | 광고 문장 구조 | 설치하고 CSS 세 줄이면 시작합니다 | 설치 뒤 CSS 세 줄을 불러옵니다 |
| 줄표 삽입 | 문장 둘을 억지로 하나로 | 밀도 우선 — compact가 기본, comfortable은 옵션 | 밀도 우선. compact가 기본이고 comfortable은 옵션입니다 |
| 동사 은유 | "심는다 · 그린다 · 모은다" | 흩어진 업무를 하나의 격자 위에 모읍니다 | 스무 가지 업무를 한 화면에서 봅니다 |
| 추상 명사 | 경험 · 가치 · 효율 · 시너지 | 더 빠르고 일관된 사용자 경험 | 같은 컴포넌트, 같은 규칙 |

이름 **Trellis(격자 · 덩굴 받침대)** 의 뜻풀이는 소개 페이지의 "이름" 한 절에서 한 번만 한다. 제목이나 버튼에 격자 은유를 다시 쓰지 않는다.

## 4. 숫자 · 단위 · 날짜

| 대상 | 표기 | 함수(contracts) | 예 |

## 5. UI 문구 패턴

| 자리 | 규칙 | 예 |
|---|---|---|
| 화면 제목 | 명사. 모듈 이름 그대로 | 전표 입력 · 결재 대기 · 재고 현황 |
| 홈 제목 | 날짜 · 맥락. 인사말 금지 | 11월 7일(금) · 본사 |
| 버튼(기본) | 동사 어간 또는 명사. 2~5자 | 저장 · 취소 · 삭제 · 등록 · 검색 |
| 버튼(결과형) | 확인 대화상자의 버튼은 결과를 말한다. "예 / 확인" 금지 | 삭제 · 반려 · 회수 |
| 등록 · 추가 · 작성 | 마스터 데이터 신규는 등록, 목록에 항목은 추가, 문서는 작성 | 거래처 등록 · 품목 추가 · 기안 작성 |
| 수정 · 삭제 | 편집 · 제거 · 지우기 대신 | 수정 · 삭제 |
| 닫기 · 확인 | 닫기는 대화상자를 닫을 때만. 확인은 정보성 대화상자에만 | |
| 폼 라벨 | 명사, 콜론 없음. 필수는 점 표시 | 거래처 · 공급가액 |
| 플레이스홀더 | 예시 값만. 라벨 대신 쓰지 않는다 | 123-45-67890 |
| 도움말 | 한 문장. 왜가 아니라 어떻게 | 세액은 공급가액의 10%로 계산됩니다 |
| 빈 상태 | 무엇이 없는지 + 다음 행동 | 이번 달 전표가 없습니다. 전표 입력에서 추가하세요 |
| 오류 | 무엇이 틀렸고 어떻게 고치는지. 사과 없음 | 사업자등록번호는 10자리입니다 |
| 토스트 | 과거형 한 문장. 되돌리기가 있으면 버튼 하나 | 저장했습니다 · 반려했습니다 |
| 알림 카드 | 모듈 타일 + 상태 한 줄 + 숫자 하나(D-35) | 결재 대기 12건 · 3일 넘은 결재 4건 |
| 결재 동작 | 올리기는 "결재 요청", 상태는 5어휘 | 결재 요청 → 진행 |
| 확인 질문 | 무엇을 하면 무엇이 되는지 | 전표 3건을 삭제합니다. 되돌릴 수 없습니다 |

| 작업지시 · 공정 · 라인 · 설비 | 워크오더 · 프로세스 · 머신 |
| 가동 · 대기 · 비가동 · 점검 | 러닝 · 아이들 · 다운 |

| 교대(주간 · 야간) · 작업자 | 시프트 · 오퍼레이터 |

## 7. 사이트 · 문서 문구

- 소개 첫 화면: 제목은 "테라스랩의 디자인 시스템 Trellis". 첫 문장은 들어 있는 것, 둘째 문장은 쓰는 제품과 플랫폼. 버튼은 시작하기 · 컴포넌트 · Figma.
- 절 제목은 **명사(원칙 · 토큰 · 컴포넌트 · 플랫폼 · 에이전트)** 를 작은 글자로 두고, 큰 제목은 평서문 하나.
- 상태를 숨기지 않는다. "npm 공개 준비 중", "Phase 1에서 추가" 같은 사실을 그대로 적는다.
- 컴포넌트 문서의 용도 절 첫 문장은 "무엇을 보여 줄 때 쓴다"로 시작한다.
- 변경 이력은 사용자에게 보이는 변화만 쓴다. 내부 리팩터링은 뺀다.

## 8. 검사

- `scripts/build-docs.mjs`의 `FORBIDDEN`(금칙어)에 §2의 수식어를 넣어 동봉 문서 빌드가 실패하게 한다. 사이트 · 테라스원 문구는 같은 목록으로 `apps/*/scripts/check.mjs`가 본문을 거른다.
- 리뷰 체크: §3 표의 신호가 하나라도 있으면 고친다. 제목에 쉼표 · 콜론 · 줄표가 있으면 고친다.
- 숫자 표기는 `formatAmount` 계열 함수로만 만든다. 문자열 템플릿으로 쉼표를 직접 찍지 않는다(린트 `trellis/no-manual-number-format`, 트랙 E 제안).
