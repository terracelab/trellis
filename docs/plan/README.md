```
Phase 3 네이티브·Django·CI   12/19 → 01/15   (1.0에 남는 것: VRT 안정화 · 번들 예산 · 다크 검수)
Phase 4 제품 적용·에이전트    01/16 → 02/27   ─▶ G3 = 1.0(디자인 시스템 완성)
```

- 게이트를 넘지 못하면 다음 Phase를 시작하지 않는다. 게이트 체크리스트는 각 Phase 파일 끝에 있다.
- Phase 1 · 2 작업은 선행 반입(D-39 · D-52 · PR-01~30)으로 대부분 진행되었다. 1.0까지는 아래 "실행 순서" 표가 Phase 순서보다 앞선다.
- Phase 2가 임계점이다. G2에서 토큰 **값**이 승인되어야 Figma 초안(D-103)을 최종 값으로 맞추고 1.0으로 간다.
- 네이티브 · Django · 제품 적용은 1.0 뒤다(D-101). 작업은 지우지 않고 상태 줄에 "1.0 뒤"와 이유를 적었다.
- 평일 저녁·주말 작업 기준이다. 작업 하나는 한 세션(1~2시간)에 끝나는 크기로 잘랐다. 더 크면 작업을 쪼개서 플랜 파일에 추가한다.

- 1.0은 저장소 태그 `v1.0.0`이다. 공개 npm · PyPI 배포는 계정이 준비되면 PF-04가 한다(D-102 제안).

## 세션 진행 절차

1. `CLAUDE.md` → 이 파일 → 현재 Phase 파일을 읽는다. 현재 Phase = 게이트를 통과한 가장 마지막 Phase의 다음(2026-11-10 G1 통과).
2. 1.0까지는 위 "실행 순서" 표에서 의존이 끝난 가장 위 줄의 작업을 고른다. 표 밖이면 상태가 `☐ 대기`이고 의존이 모두 `☑`인 가장 앞 작업을 고른다. `◐ 진행` 중인 작업이 있으면 그것을 먼저 끝낸다. `☐ 1.0 뒤` 작업은 고르지 않는다.
3. 상태를 `◐ 진행`으로 바꾸고 작업 ID와 목표를 한 줄로 말한다.
4. 규격 문서(`docs/spec/*`)에서 그 작업이 따라야 할 절을 읽는다. 규격에 없는 결정이 필요하면 `decisions.md`의 "원문과 다른 점" 표에 **추가**하고 진행한다(사람이 나중에 뒤집을 수 있게).
5. 구현 → 완료 조건의 명령을 **실제로 실행**해 출력으로 증명 → 상태를 `☑ 완료 날짜`로 바꾼다.
6. 커밋(Conventional Commits + changeset). 세션 끝 메시지에 작업 ID, 증명한 명령, 다음 작업 ID를 쓴다.

## 완료 정의(DoD)

**모든 작업 공통**
- 완료 조건의 명령이 전부 통과하고 출력이 세션 로그에 남아 있다.
- `pnpm lint && pnpm typecheck && pnpm test`가 레포 전체에서 통과한다.
- 공개 패키지 변경이면 changeset이 있다.

**컴포넌트 작업 공통(P0·P1·P2 컴포넌트 전부)** — 각 컴포넌트 작업의 완료 조건에 이 목록이 포함된 것으로 본다.
1. `packages/contracts/src/<Name>/spec.md` 가 `docs/spec/components.md` §3 템플릿의 모든 절을 채웠다.
2. `packages/contracts/src/<Name>/<Name>.contract.ts` 가 있고 `defineContract`로 내보낸다.
3. 웹 구현 `packages/react/src/<Name>/` 이 contract 타입을 `satisfies` 하고, `_headless` 어댑터 외의 Base UI 직접 import가 없다.
4. 스토리: 모든 variant × size 조합 1개 이상, `States` 스토리(7 상태 전부), density 두 모드에서 깨지지 않음. States를 그릴 수 없는 경우는 D-105(제안).
5. 테스트: 렌더·키보드 조작·contract 테스트가 통과한다.
6. a11y: Storybook a11y 애드온(axe)에서 violation 0.
7. VRT: 스냅샷이 `apps/storybook/vrt/__snapshots__/<Name>/` 에 커밋되어 있다(Light·Dark × compact·comfortable).
8. 린트: raw hex·px·font-family 0, primitive 토큰 참조 0.
9. `pnpm --filter @terracelab/trellis-react build` 가 `<Name>` 엔트리를 내보낸다. D-105(제안)를 받으면 루트 엔트리가 `<Name>`을 내보내고 트리셰이킹되는 것으로 읽는다.
10. 네이티브 구현이 이 Phase 범위이면 3~5·7(스냅샷은 jest)·9를 `packages/native`에도 적용한다. 네이티브는 1.0 뒤다(D-101).
