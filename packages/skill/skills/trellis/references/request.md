# Trellis 보강 요청

서비스를 만들다 Trellis에 없거나 모자란 것을 찾으면 그 자리에서 기록한다. 기록하는 곳은 서비스 저장소의 `.trellis/requests.md` 한 곳이다. Trellis 쪽에서 `node scripts/collect-requests.mjs <서비스 경로>`로 여러 서비스의 파일을 모아 Trellis 작업 목록에 옮긴다. 이 기록이 Trellis의 다음 작업 목록이 된다.

## 바로 고치는 것(하위 모듈에서)

버그, 문구, 스타일 한 곳처럼 공개 API를 바꾸지 않는 수정.

1. `git -C trellis switch main`으로 브랜치에 올린다(클론하거나 업데이트한 뒤에는 커밋에 고정돼 있을 수 있다). `trellis/`에서 고친다. `trellis/CLAUDE.md`의 절대 규칙을 지킨다(토큰 밖 값 금지, semantic만, spec 먼저).
2. 서비스 루트에서 `pnpm ds:build`로 Trellis가 빌드되는지 확인하고, 바꾼 컴포넌트를 쓰는 화면을 눈으로 본다.
3. `trellis/` 안에서 커밋한다(Conventional Commits, scope는 패키지 이름). push는 사람이 정한다(`git -C trellis push`).
4. 서비스 저장소에서 하위 모듈 포인터 변경을 커밋한다(`git add trellis`).

## 요청만 남기는 것

새 컴포넌트, 새 props, 토큰 값 · 이름, 블록 구조 변경, 문서가 틀린 곳. 서비스에서는 기존 조합으로 버틴다.

서비스 저장소의 `.trellis/requests.md` 표 맨 아래에 한 줄을 더한다. 이 일로 `trellis/` 하위 모듈을 고치지 않는다. 파일이 없으면 아래 머리줄로 만든다.

```markdown
| 날짜 | 서비스 | 종류 | 내용 | 임시 처리 | 상태 |
|---|---|---|---|---|---|
```

| 칸 | 쓰는 법 |
|---|---|
| 날짜 | 2026-11-09 |
| 서비스 | 서비스 이름 |
| 종류 | 컴포넌트 · props · 토큰 · 블록 · 버그 · 문서 |
| 내용 | 무엇이 없어서 어떤 화면에서 막혔나. 한두 문장. 줄바꿈과 `\|` 없이 |
| 임시 처리 | 서비스에서 지금 어떻게 버티고 있나 |
| 상태 | 요청. Trellis에서 고쳐 받은 뒤에는 `완료(커밋)` |

같은 요청이 이 파일에 이미 있으면 새 줄을 만들지 않고 그 줄의 내용을 고친다. Trellis 쪽 목록에 이미 있는지는 찾지 않아도 된다. 모으는 스크립트가 이미 옮긴 줄을 거른다.

보고할 때는 이번 작업에서 더한 줄을 함께 적는다.
