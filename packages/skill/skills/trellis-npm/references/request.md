# Trellis 보강 요청

서비스를 만들다 Trellis에 없거나 모자란 것을 찾으면 그 자리에서 기록한다. 서비스에서 새 컴포넌트를 만들지 않고, 가장 가까운 기존 컴포넌트 조합으로 둔다.

## 무엇을 남기나

새 컴포넌트, 새 props, 토큰 값 · 이름, 문서가 틀린 곳, 버그.

## 어디에 남기나

서비스 저장소의 `.trellis/requests.md` 표 맨 아래에 한 줄을 더한다. 파일이 없으면 아래 머리줄로 만든다.

```markdown
| 날짜 | 서비스 | 종류 | 내용 | 임시 처리 | 상태 |
|---|---|---|---|---|---|
```

| 칸 | 쓰는 법 |
|---|---|
| 날짜 | 2026-11-09 |
| 서비스 | 서비스 이름 |
| 종류 | 컴포넌트 · props · 토큰 · 버그 · 문서 |
| 내용 | 무엇이 없어서 어떤 화면에서 막혔나. 한두 문장. 줄바꿈과 `\|` 없이 |
| 임시 처리 | 서비스에서 지금 어떻게 버티고 있나 |
| 상태 | 요청. Trellis 새 버전에서 받은 뒤에는 `완료(버전)` |

같은 요청이 이 파일에 이미 있으면 새 줄을 만들지 않고 그 줄의 내용을 고친다.

## Trellis에 전하기

Trellis 저장소의 이슈로 올리는 일은 사람이 정한다. 주소는 `https://github.com/terracelab/trellis/issues`다. 보고할 때 이번 작업에서 더한 줄을 함께 적고, 이슈로 올릴 만한 것을 알린다.

`node_modules` 안의 Trellis 파일을 고치지 않는다. 다시 설치하면 사라진다.
